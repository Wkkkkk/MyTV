## Shipped features

### On-demand VOD cluster

- **Core channel type (#45)**: `vod_on_demand` channels play a hand-navigated playlist; playback cursor persists in `localStorage`; playback stops silently after the last item (no loop). New endpoints `GET /channel/:id/playlist` and `GET /channel/:id/item/:item_id`; `channels_json` now carries `type` so the client branches before tuning. Admin gets a type-dropdown option and playlist-item management. Migration 007 made non-destructive.
- **Per-item EPG blocks (#52)**: the guide renders one clickable block per active playlist item (fixed-width slots, `ON_DEMAND_ITEM_WIDTH_PCT = 25.0`, ≈ 4 visible). Clicking a block tunes the channel and jumps directly to that item via a new `ProgramSlot.item_id` field. An empty playlist falls back to a single full-width tunable block.
- **Dead-item handling (#53)**: `playlist_item::apply_health_result` owns the auto-disable rule (reusing the shared `source::FAILURE_THRESHOLD` via the pure `is_dead` predicate). Both the background health loop and interactive tune call it. The player toasts and auto-skips dead on-demand items to the next playable one. Admin source rows surface the disable reason on inactive items.
- **Stale-item reaper (#54)**: any playlist item that has been disabled for > 3 days is hard-deleted at the 15-min health tick (`playlist_item::reap_stale_disabled`). Migration 008 adds a nullable `disabled_at` column backfilled to `now` so pre-existing disabled rows get a grace period before their first reap. Clock invariant (`disabled ⇒ disabled_at set; active ⇒ NULL`) is maintained by `set_active` and `update_health`, preventing a continuously failing item from resetting its own clock.

### Player overlay redesign (#51)

- Native `<video controls>` replaced by custom chrome: play/pause button, scrubber + time display, ⏮/⏭ item navigation, ☰ playlist panel, fullscreen (`#player-panel` — keeps custom chrome visible).
- **Touch gesture layer**: single tap toggles chrome (3s auto-hide), double-tap near a left/right edge seeks ±10s (seekable types only), vertical swipe navigates; multi-touch and pinch ignored.
- **Unified vertical navigation**: `↑`/`↓` and swipe-up/down treat the whole channel feed as one continuous list — on-demand channels expand into their items; stepping past a playlist edge overflows into the adjacent channel; the feed wraps at both ends.
- Seek (`←`/`→`, double-tap, scrubber) enabled for `vod_on_demand` in addition to `vod_loop`. Keyboard map finalized: `Space` play/pause, `↑↓` navigate, `←→` seek, `F` fullscreen, `Esc` close, `?` help cheat-sheet.
- Frontend-only change — no backend, API, DB, or migration changes.
