Playlist Item Integrity

One targeted correctness fix. VOD items uploaded through the JSON API (publish-video plugin) no longer land at sort_order = 0 or pile up as duplicates — the API now auto-appends at max + 1 and silently returns the existing item on a re-upload.

01 The Fix — Two New Model Functions
next_sort_order()
src/model/playlist_item.rs

Computes MAX(sort_order) + 1 for the channel, used by both create paths when the caller doesn't pin a sort_order. Fixes the root cause of every item landing at 0 when added via the JSON API.

find_duplicate()
src/model/playlist_item.rs

Channel-scoped lookup matching on url OR title — catches re-encoded copies of the same video, not just exact-URL duplicates. Shared by both create paths, so no entry point can write a duplicate row.

Before ✗ Items added via the API landed at sort_order = 0; duplicate rows accumulated on every re-upload.
After ✓ Appended at max + 1; a re-upload returns the existing item, HTTP 200 — silent and idempotent.
02 Two Paths, One Guard
API create src/routes/api/playlist.rs

Calls find_duplicate first; on a hit, returns the existing item with a HTTP 200 silent idempotent skip. On a miss, calls next_sort_order when sort_order is omitted.

Admin form src/routes/admin/playlist.rs

Same dedup guard, mirroring the API. The form already auto-incremented in the UI, but the DB path had no server-side guard until now.
