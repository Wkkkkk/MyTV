# Weekly Progress Pages site (idea #55) — design

**Date:** 2026-06-17
**Status:** Approved design, pending implementation plan
**Idea:** [#55 in `docs/IDEAS.md`](../../IDEAS.md)

## Goal

Publish the weekly editorial progress cards (`docs/progress/<date>-week-card.html`,
generated by the local `mytv-weekly-card` launchd job) as a designed, self-regenerating
static **GitHub Pages** microsite at `https://wkkkkk.github.io/MyTV/`. The site is a small
project "build log": a featured latest week, recent weeks, a complete archive timeline, plus
two standing reference sections (architecture, incidents).

Non-goals: no backend, no database, no markdown→HTML rendering in the build (v1), no change
to the card-generation job.

## Context & constraints

- Cards are **self-contained HTML** on a fixed `2000×1500` (4:3) canvas, with embedded CSS,
  Google-font links, and a `@media (max-width:1000px)` rule that reflows the poster into a
  single readable column. The editorial palette is paper `#f5f3ed` / ink `#1a1a1a` / accent
  `#b5341f`, fonts Noto Serif SC + Inter + Oswald, on a `#2a2a2a` backdrop.
- The repo is **public**, so `docs/` is already world-readable; Pages adds no new exposure.
- The `mytv-weekly-card` launchd job commits `<date>-week-card.html` (+ matching `<date>-week.md`)
  to `docs/progress/` on `main`. This job is **unchanged** by this work.
- CI already uses GitHub Actions; the existing Rust CI workflow stays separate from this one.
- An `architecture-diagram.html` (real HTML) and several markdown deep-dives already exist under
  `docs/architecture/`; two writeups exist under `docs/bug-logs/`.

## Decisions (locked during brainstorming)

| Topic | Decision |
|-------|----------|
| Curation | Publish **all** weeks automatically; index features the latest + 2 recent inline, all weeks in the archive timeline. |
| Card embedding | **Hybrid**: hero & recent render as **scaled 4:3 posters**; archive/recent click-through opens a **reflow** (readable single-column) view. |
| Build/deploy | **GitHub Action** on push under `docs/progress/**`; builds the site and deploys via `actions/deploy-pages`. |
| Page chrome | **Rich landing**: masthead, expanded About, hero, recent 2, full timeline, Architecture section, Incidents section, footer. |
| Standing sections (F/G) | Link to **GitHub-rendered** markdown docs; the architecture diagram (HTML) links/embeds directly. No markdown rendering in the build. |
| Build language | **Python 3, stdlib only** (no third-party deps; runs on the GitHub runner). |

## Architecture

Decoupled pipeline. The card job produces inputs; an independent Action consumes them.

```
mytv-weekly-card (launchd, local)         GitHub Action (.github/workflows/pages.yml)
  └─ commits docs/progress/<date>-*.html ──push──▶ build.py ──▶ site/ ──▶ deploy-pages
```

### Components (each independently testable)

**`scripts/progress_site/build.py`** — three pure-ish units:

1. **discover(progress_dir) → [Week]**
   Scan `docs/progress/`, match files named `^(\d{4}-\d{2}-\d{2})-week-card\.html$`.
   Parse the week-ending date from the filename. Pull display metadata from the **card HTML**
   (single parse target, stable class names — see Data model). The matching
   `<date>-week.md` is used only as a fallback for the headline if the card lacks a `.title`.
   Return a list of `Week` records sorted by date **descending** (newest first).
   Pure function of the directory contents.

2. **render(weeks, templates) → {index_html, detail_pages}**
   Fill `template.html` placeholders to produce `index.html`:
   - **Hero** = `weeks[0]` (poster iframe + label + link to full card).
   - **Recent** = `weeks[1:3]` (smaller poster iframes; link to detail/reflow).
   - **Timeline** = `weeks[:]` (all weeks; dated rows → detail/reflow).
   - **Architecture** and **Incidents** = static section content from a small declared
     list of `{title, blurb, href}` entries (see Standing sections).
   Also produce one **detail page** per week from `detail-template.html` (reflow view).
   Pure function of the inputs.

3. **assemble(render_output, progress_dir, static_dir) → site/**
   Write `index.html`, the detail pages, copy each `<date>-week-card.html` into `site/cards/`,
   copy `static/favicon.svg`. Produces the deployable `site/` tree.

**`scripts/progress_site/template.html`** — the page shell (masthead, About, section
scaffolding, footer) with `{{...}}` placeholders. Pure HTML/CSS, editable independently of the
Python. Carries the editorial palette/fonts so the chrome matches the cards.

**`scripts/progress_site/detail-template.html`** — per-week reading page: site-lite chrome,
a "← back to index" link, the card embedded in a **reflow** iframe, and a "view as poster ↗"
link to the raw card file.

### Poster vs. reflow embedding (precise mechanism)

The card's poster⇄column switch is driven by its own `@media (max-width:1000px)` rule, which
keys off the **iframe's** viewport width:

- **Poster** (hero, recent): `<iframe>` given a logical width **≥1000px** (its native 2000px),
  then CSS-`transform: scale(...)` down to fit a `aspect-ratio:4/3` box in the page column.
  The card stays in its designed multi-column poster layout.
- **Reflow** (detail pages): `<iframe>` given a width **<1000px** (≈860px reading column), so
  the card renders its single-column mobile layout at readable size — no scaling, full text.

### `site/` artifact structure

```
site/
  index.html
  favicon.svg
  cards/
    2026-06-15-week-card.html        # copied verbatim (raw poster, opens full)
  week/
    2026-06-15.html                  # generated reflow detail page
```

All asset/iframe references are **relative**, so the site works under the
`/MyTV/` project-Pages sub-path.

## Data model — `Week`

Extracted per week from the **card HTML** (stable class names already present):

| Field | Source in card | Used by |
|-------|----------------|---------|
| `date` | filename `YYYY-MM-DD` (week-ending) | sort, permalink, labels |
| `range_label` | `.kicker` text, range portion (e.g. "09 → 15 Jun 2026") | hero/recent/timeline labels |
| `headline` | `.title` inner text (strip `<br>`) | hero, recent, timeline |
| `deck` | `.deck` text | timeline subline, detail intro |
| `commits` | leading integer of `.statblock .big` | hero stat, timeline count |
| `card_file` | `cards/<date>-week-card.html` | poster iframe, "full" link |
| `detail_file` | `week/<date>.html` | recent/timeline click-through |

If `.title` is absent, fall back to the first heading in `<date>-week.md`, else
"Week ending `<date>`". Missing `.deck`/`.statblock` degrade gracefully (omit subline/stat).

## Page content (top → bottom)

- **A — Masthead.** MyTV logo (from `static/favicon.svg` / `branding/icons`) + "Weekly Progress".
- **B — About.** What MyTV is (Rust · Axum · SQLite · HTMX, single-user IPTV on a 256 MB box);
  that the poster is auto-generated every Friday from git history; a one-line "how to read a
  poster"; a meta strip — Live `kunstv.fly.dev`, Source repo, test count, since-year.
- **C — Hero.** Latest week as a scaled poster; label + "view full card ↗" (raw card).
- **D — Recent.** Previous 2 weeks as smaller posters; click → detail (reflow). Empty until weeks accrue.
- **E — Timeline / archive.** All weeks as dated rows (range label · headline · deck subline ·
  commit count) → detail (reflow). The complete index/nav spine.
- **F — Architecture** *(standing)*. A feature card linking the interactive
  `architecture-diagram.html`, plus a grid linking the deep-dive docs (tune-flow, yt-dlp
  resolution, health checker, database ER, request route map, source status). Links target the
  GitHub-rendered docs.
- **G — Incidents / bug log** *(standing)*. The writeups under `docs/bug-logs/`
  (yt-dlp OOM 2026-06-10, hop-by-hop headers 2026-06-03), date + one-line, linking GitHub-rendered.
- **H — Footer.** "Generated weekly from git history · idea #55" + links to live app and repo.

The standing-section entries (F, G) are a small **declared list** in the build (title, blurb,
GitHub href), not auto-discovered, so they stay curated and stable.

## GitHub Action — `.github/workflows/pages.yml`

- **Triggers:** `push` to `main` on paths `docs/progress/**`, `scripts/progress_site/**`,
  and `.github/workflows/pages.yml`; plus `workflow_dispatch` (manual rebuild).
- **Permissions:** `pages: write`, `id-token: write`, `contents: read`.
- **Concurrency:** a `pages` group so overlapping pushes don't race the deploy.
- **Steps:** checkout → run `python3 scripts/progress_site/build.py` (writes `site/`) →
  run `build_test.py` as a guard (optional but recommended) → `actions/upload-pages-artifact`
  (`path: site/`) → `actions/deploy-pages` (environment `github-pages`).
- Independent of the existing Rust CI workflow.

## Testing

`scripts/progress_site/build_test.py` (stdlib `unittest`) against a small fixture dir under
`scripts/progress_site/fixtures/` containing 3–4 minimal card HTML files (+ one missing-`.md`
case):

- **discover:** correct date parse; descending sort; metadata extracted from card classes;
  headline fallback when `.title` missing; tolerates missing `.md`/`.deck`/`.statblock`.
- **render:** newest week in the hero slot; exactly two in "recent"; **all** weeks in the
  timeline; every `iframe`/anchor `href` resolves to a file that `assemble` writes into `site/`.
- **assemble:** `site/` contains `index.html`, one `week/<date>.html` per week, and a copied
  `cards/<date>-week-card.html` per week; relative paths only.

Run locally and as a guard step in the Action before deploy.

## One-time manual prerequisites (cannot be committed)

1. Repo **Settings → Pages → Source = GitHub Actions** (enables the deploy environment).
2. Confirm site URL `https://wkkkkk.github.io/MyTV/`; relative paths assumed throughout.

These are documented here and called out at deploy time.
